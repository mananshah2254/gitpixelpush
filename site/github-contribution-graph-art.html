Contribution calendar guide

How to make GitHub contribution graph art

Your GitHub profile shows a grid of days. You can design a picture on that grid by creating commits dated for those squares. The important part is being clear that it is art, not a record of work you did on those dates.

1. Understand what the squares mean

Each column represents a week and each square a day. Color intensity reflects contribution counts, so a design needs dates and different commit counts—not merely an uploaded image. Existing genuine activity may already color some squares, and your profile settings affect what visitors see.

GitHub has specific rules for which commits count, including branch, email association, and repository conditions. Review GitHub's contribution reference before assuming a commit will appear. A new contribution may take time to show up.

2. Sketch first, publish second

Choose a simple shape or a short word that fits 7 rows. Preview the dates and estimated commit count before writing anything. If you use GitPixelPush, you paint directly over your current graph, set one of four ink levels, and review the planned commits before publishing.

3. Keep the result honest

Backdated commits can be misleading if presented as real coding activity. GitPixelPush labels generated commits and documents the artwork in the created repository. Do not use graph art to imply work history, experience, or streaks you did not earn.

What the tool changes.

With your permission, GitPixelPush creates or reuses a repository you name and writes the graph-art commits there through GitHub's API. It does not edit your existing project repositories. A private repository requires GitHub's broader repository permission, so review the authorization screen carefully.

4. Check the profile, then clean up if needed

After publishing, open your GitHub profile to check the actual graph. If squares are missing, check the repository's default branch, commit email and contribution settings using GitHub's troubleshooting guide. Appearance is determined by GitHub, not guaranteed by the drawing tool.

To remove the art, delete the repository containing the generated commits. To stop future access, revoke the app in your GitHub application settings.

Before you publish: a practical checklist

  • Preview the shape on the seven-row calendar and check which dates already have real activity. The finished profile may not look exactly like an empty-grid preview.
  • Check the proposed repository name, visibility, and commit count. Private contributions may be hidden from the public graph unless your GitHub profile is set to display them.
  • Make sure you are comfortable with the authorization scope. A public graph-art repository uses a narrower scope than creating a private one.
  • Keep the generated repository's explanation visible. The art should not be mistaken for a record of work done on those historical dates.

If a square does not appear, do not keep publishing extra commits blindly. First compare its date and branch with GitHub's contribution rules. You can stop, inspect the generated repository, and remove it if the result is not what you intended.
